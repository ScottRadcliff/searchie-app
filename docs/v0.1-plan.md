# Searchie v0.1 plan

## Goal

Deliver a useful command-line search tool with a reusable Elixir core, a repeatable Docker development environment, and clear documentation.

Estimated effort: three focused work sessions, roughly 10–20 hours across 1–3 days. These are planning estimates; implementation and verification may reveal additional work.

## Milestone 1: Development setup

Estimated effort: 2–4 hours.

- [x] Add a development `Dockerfile`, `compose.yaml`, and `.dockerignore`, following the `dev-server-setup` skill.
- [x] Use one Elixir service with no database or exposed ports.
- [x] Mount the project for development and keep container build artifacts separate from the host's `_build` directory.
- [x] Provide a persistent development container for interactive shell and console access.
- [x] Add a Makefile with `help` as its default target.
- [x] Provide `build`, `up`, `down`, `stop`, `restart`, `logs`, and `ps` targets. Keep `up` attached and retain volumes during routine shutdown.
- [x] Provide `shell` and `console` targets for a running container; load Searchie in IEx.
- [x] Provide `test`, `format`, `check`, and `search` targets that work without an already-running container.
- [x] Support a search invocation such as `make search SEARCH_PATH=sample.txt QUERY=alpha`.
- [x] Document first-run commands and how to mount and search files outside the project.
- [x] Validate Compose configuration, build the image, and verify search, console, formatting, and tests in Docker.

Verification: the Docker image built successfully; `make check` passed formatting checks and all 19 tests. Verified `make format`, file and directory searches, a read-only external mount, persistent container startup, shell availability, and interactive `make console` with Searchie loaded. Temporary verification containers were removed; named volumes were retained.

## Milestone 2: Core usability

Estimated effort: 4–8 hours.

- [x] Add conventional CLI flags for count, context, and color while retaining existing `--modifier` syntax.
- [x] Add case-insensitive matching.
- [x] Add optional line numbers, using `path:line:text` for directory results.
- [x] Add file include and exclude patterns so users can limit searches and skip directories such as `_build` and `.git`.
- [x] Keep searching in the reusable `Searchie` module and argument parsing and presentation in the CLI layer.
- [x] Define consistent API options, result metadata, and behavior when options are combined.
- [x] Add focused tests for new behavior and update usage examples.

Verification: formatting checks and all 35 tests passed locally and in Docker. Coverage includes mixed legacy and standard options, precedence, negated flags, case-insensitive literal and regex highlighting, Unicode matching, line numbers, include/exclude patterns, hidden files, context, and invalid arguments. Docker smoke tests verified combined flags and colored regex results.

## Milestone 3: Reliability and release

Estimated effort: 4–8 hours.

- [x] Stream file reads rather than loading entire files into memory; account for context output as well as initial matching.
- [x] Report unreadable files and other filesystem failures instead of silently treating them as files with no matches.
- [x] Define predictable exit codes for matches, no matches, and errors, including partial failures in directory searches.
- [x] Add an escript entry point so users can invoke `searchie` outside the repository.
- [x] Document the Erlang runtime requirement for the escript.
- [x] Verify CLI output, exit codes, error handling, recursive searches, and standalone execution.
- [x] Update the README to accurately describe installation, examples, supported options, and limitations.

Verification: the Docker image built successfully, and formatting checks and all 50 tests passed locally and in Docker. Packaged escript tests run outside the repository and verify match/no-match/error exit codes, help, context, recursive searches, and partial failures. Streaming tests cover 100,000 matching lines without retaining matches, adjacent and boundary context, physical-line semantics, invalid UTF-8, filesystem failures, and symlink cycles. A separate Docker check under UID 65534 verified unreadable files and directories: successful matches were retained, diagnostics went to stderr, and the executable exited 2. The development escript was built successfully and is available as `./searchie` (ignored by Git).

The standalone executable owns process exit codes. The Mix task and `Searchie.CLI.run/1` remain safe to invoke repeatedly in IEx and return statuses without halting the VM. The README documents this distinction, runtime requirements, partial-result errors, and memory limits.

## Completion criteria

The v0.1 milestone is complete when:

- A fresh checkout can build, search, and run tests through Docker without a host Elixir installation.
- The packaged escript can run outside the project on a machine with the required Erlang runtime.
- Searches support literals, regular expressions, case-insensitive matching, optional line numbers, context, highlighting, and matching-line counts.
- Directory searches support file inclusion and exclusion.
- Large-file searches do not require retaining the entire file in memory.
- Errors and exit codes are documented and behave predictably.
- Relevant tests pass and the documented commands have been verified.

## Deferred work

These items are outside the v0.1 scope:

- A Codex skill or specialized agent workflow.
- Hex publication; revisit when another Elixir project needs the search API.
- Full `.gitignore` compatibility.
- JSON output.
- Whole-word matching.
- Merging overlapping context blocks.
- Advanced performance optimization and parallel searching.

The intended outcome is a finished small tool with a reusable core. Package publication and specialized workflows can follow as separate milestones driven by concrete use cases.
